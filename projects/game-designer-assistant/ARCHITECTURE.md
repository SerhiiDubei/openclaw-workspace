# Game Designer Assistant — Beta Architecture

## Core Principle: Learn by Doing
Цей скіл створюється через реальні сесії. Кожна сесія = дані для покращення.

## 1. Структура (мінімальна, розширювана)

```
game-designer-assistant/
├── SKILL.md                      # Короткий, з TODO-маркерами
├── BETA.md                       # Лог змін, гіпотези, рішення
├── scripts/
│   ├── db.py                     # Проста SQLite, мігрується
│   ├── log-session.py            # Запис сесії з тегами
│   └── quick-export.py           # Мінімальний експорт
├── references/
│   ├── mechanics-draft.md        # Чернетка механік (редагується)
│   ├── question-patterns.md      # Шаблони питань
│   └── sessions/                 # Логи реальних сесій
│       ├── 2026-03-13-bar-quiz.md
│       └── 2026-03-XX-team-game.md
└── _learning/                    # Мета-навчання
    ├── hypotheses.md             # Що ми тестуємо
    ├── decisions.md              # Чому прийняли так
    └── metrics.md                # Що працює, що ні
```

## 2. База (мінімум для старту)

```sql
-- Тільки те, що потрібно зараз
CREATE TABLE sessions (
    id TEXT PRIMARY KEY,
    date TEXT,
    game_type TEXT,        -- bar|home|corporate
    player_count INT,
    duration_min INT,
    mechanics_used TEXT,   -- JSON ["quiz", "blitz"]
    questions_used TEXT,   -- JSON [...]
    notes TEXT,            -- що спрацювало/ні
    tags TEXT              -- beta, test, production
);

CREATE TABLE mechanics (
    id TEXT PRIMARY KEY,
    name TEXT,
    description TEXT,
    status TEXT,           -- draft|tested|approved
    first_used TEXT,       -- дата першого тесту
    tags TEXT              -- fast, team, bluff, etc
);

CREATE TABLE questions (
    id TEXT PRIMARY KEY,
    text TEXT,
    topic TEXT,
    difficulty INT,
    format TEXT,           -- bar|blitz|circle|donetki
    source TEXT,           -- manual|generated|modified
    session_id TEXT,       -- де використано вперше
    rating INT             -- 1-5 зворотний зв'язок
);
```

## 3. Workflow "Сесія формує скіл"

### Перед грою (підготовка)
```
Користувач: "Завтра гра на 15 людей, 40 хв, бар"
→ Скіл: що зробити?
→ Ми: обираємо 2-3 механіки з draft
→ Генеруємо/беремо питання
→ Експортуємо в простий формат
```

### Після гри (вивчення)
```
Користувач: розповідає що було
→ Скіл записує в sessions/
→ Оновлює rating питань
→ mechanics.status: draft → tested (якщо спрацювало)
→ Додає нотатки в BETA.md
```

### Ретроспектива (коли накопичиться)
```
Аналізуємо 5-10 сесій
→ Що повторюється? → виносимо в patterns
→ Що не працює? → видаляємо/змінюємо
→ Оновлюємо SKILL.md
```

## 4. BETA.md — серце процесу

```markdown
# Beta Log

## Гіпотези (тестуємо)
- [ ] Механіка "Бліц по колу" підходить для 10+ людей
- [ ] Складність 3 — оптимум для аудиторії 30-40
- [ ] Донетки краще працюють у другій половині гри

## Сесії

### 2026-03-XX: Бар, 15 людей
- Механіки: ["quiz-bar", "blitz-circle"]
- Результат: blitz-circle — 🔥, quiz-bar — 😐
- Висновок: потрібно більше соціальної взаємодії
- Дії: додати механіку "team-debate"

## Рішення архітектури
- 2026-03-13: Вирішили не робити автоматичну генерацію покищо — 
  спочатку 20 ручних питань, щоб зрозуміти патерни
```

## 6. Наступні кроки (пріоритети)

### Фаза 1: Сирі дані (зараз)
- [ ] Створити структуру папок
- [ ] Заповнити mechanics-draft.md 5-10 механіками
- [ ] Додати 20 питань вручну з твоїх минулих ігор
- [ ] Перша тестова гра

### Фаза 2: Перші сесії (після 3-5 ігор)
- [ ] Аналіз що спрацювало
- [ ] Оновлення механік
- [ ] Додавання нових форматів

### Фаза 3: Автоматизація (коли зрозуміло що робити)
- [ ] Генерація питань
- [ ] Автоматичний підбір механік
- [ ] Валідаційні сесії

Що скажеш? Почнемо з Фази 1 — створю структуру і заповнимо початковими даними? 
Мені потрібно:
1. Твої 3-5 улюблених механік (які точно працюють)
2. 10-15 питань з минулих ігор (щоб зрозуміти стиль)
3. Дата наступної гри (щоб спланувати першу сесію)
